# Benchmarks

The baseline is a fixed 20-turn set run against the real local model. It exists
so every V.0.1 performance claim can be compared with the same tasks, model and
Mac rather than with a memory of how fast something felt.

## Running

```bash
npm run bench       # 20 turns, writes docs/benchmarks/v0.0-baseline.json
npm run bench:rss   # idle RSS, updates the same baseline if present
```

`bench` uses an isolated temporary data directory, a fresh commitment ledger,
a temp memory file and a tool context that denies every confirmation. It never
plays audio, opens an app, writes a note or touches the real Lux data. The fixed
tasks are read-only by design.

Run `bench` first. `bench` unloads the chat model before starting the engine so
`coldStartMs` is a genuine cold start, not a model that was already resident.
`bench:rss` starts the built app separately and waits for it to settle.

## Definitions

| Field | Definition |
| --- | --- |
| `wallMs` | `runAgent` start → final answer |
| `ttftMs` | turn start → first non-thinking content token |
| `ttfswMs` | turn start → the full reply is handed to speech. V.0 speaks only after the loop, so this equals wall time; Phase 2 changes it to the first sentence. |
| `promptTokens` | sum of Ollama `prompt_eval_count` across model rounds |
| `evalTokens` | sum of Ollama `eval_count` across model rounds |
| `cachedPromptTokens` | sum of `prompt_eval_cached_count` |
| `cacheReusePct` | `cachedPromptTokens / promptTokens`, weighted across the turn |
| `rounds` | model rounds, including the final answer round |
| `toolRounds` | rounds that contained at least one tool call |
| `success` | `checkBenchTask` in `shared/bench.ts` passed |
| `coldStartMs` | benchmark process boot → engine reports `ready` with the model warmed |
| `idleRssMb` | sum of RSS across the app and all child processes after the settle window; Ollama is separate and not counted |

The per-turn result also includes the tool calls and their status, so a faster
turn that skipped a required read is visible rather than silently counted as a
win.

## Task mix

- 5 trivial turns, including two that should use no tool at all
- 5 one-tool turns
- 5 multi-tool turns (success requires the named tools)
- 3 research turns with a citation check
- 2 deliberately ambiguous turns; one may pass by asking one targeted question

## Caveats

- Single-machine measurements on an M4 MacBook Air, 16 GB. Not a controlled lab.
- Network tasks depend on the network and on the current state of public pages.
- The model is whatever `settings.model` names at run time; the report records
  it.
- A failed task is kept in the report with its reason. Do not average it away.
- `bench` exits non-zero if any task fails, but still writes the full report.

## Files

- `v0.0-baseline.json` — the untouched V.0 run, generated by `npm run bench`
- `idle-rss.json` — the idle RSS sample, generated by `npm run bench:rss`
- `raw/v0.0-baseline.raw.json` — full replies and tool summaries, kept local and ignored by git because clipboard text, file paths and page content can be personal. The committed report redacts them.
